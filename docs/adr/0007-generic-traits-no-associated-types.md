# ADR-0007: トレイトはジェネリック・関連型なし・複数 instantiation 可・スーパートレイトあり

## Status
Accepted・実装済み（ジェネリックトレイト `trait Iterator<T>`・スーパートレイト `trait Sub: Super`
を実装。適合検査がスーパートレイト実装を要求し、`<T: Sub>` 境界からスーパートレイトのメソッドを
解決できる。複数 instantiation・`#Iterator<i32>` 修飾は型検査レベルで対応。関連型なし。）

## Context
トレイトの「形」を決める: 要素型（Iterator の要素など）をどう表すか、同じトレイトを
複数の型引数で実装できるか、トレイト間の要求関係をどう書くか。

## Decision

### ジェネリックトレイト（関連型なし）
- トレイトは型パラメータを持てる: `trait Iterator<T> { fn next(&mut self): Option<T> }`。
- **関連型（associated type）は持たない**。要素型はトレイトの型引数で表す。

### 複数 instantiation を許す
- 同じトレイトを複数の型引数で実装してよい:
  `impl Iterator<i32> for C` と `impl Iterator<string> for C` を同居できる。
- 曖昧は ADR-0004 の `#` を**型引数まで**拡張して解く:
  `c.next#Iterator<i32>()`、`for x#i32 in c`。提供元が1つなら素の `c.next()` / `for x in c`。

### スーパートレイト（`trait Sub: Super`）
- 別トレイトを要求する**有向の関係**を `:` で書く: `trait Ord: Eq { ... }`、
  複数要求は `trait Sub: Eq + Show`（要求集合の列挙に `+` を使う）。
- 意味論: (1) `impl Sub` には `impl Super` が必要、(2) Sub のメソッド/デフォルト本体で
  Super を仮定できる、(3) `<T: Sub>` は `T: Super` を含意する。
- **無関係なトレイトの合成 `A + B`（ADR-0001）とは別概念**。`+` は交差、`:` は要求。

## Considered Options
- **関連型** vs **ジェネリックトレイト**（採用）: 関連型は「1型1実装」で綺麗だが、「1つの型を
  複数の要素型で反復する」柔軟さを失う。ジェネリックトレイトを採り、曖昧は `#` で明示解決。
- **スーパートレイトを `+` で代替**（却下）: `+` は無関係な能力の交差であり、Ord が Eq を
  要求する有向関係とは意味が違う。`<T: Sub>` が Super を含意する旨味も合成では出せない。

## Consequences
- 表現力が高い（複数反復）。曖昧は呼び出し側 `#` で断つ（iris の「衝突は明示」原則・ADR-0004）。
- 関連型を持たないぶん、要素型はトレイト型引数として露出する。本物の関連型が欲しくなったら
  後日再検討する。
