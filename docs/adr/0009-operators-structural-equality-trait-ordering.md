# ADR-0009: 等価 `==` は構造的既定＋`Eq` 上書き、順序・算術は明示トレイトのみ

## Status
Accepted（設計確定。struct の構造的 `==` の codegen・各演算子トレイトはこれから。）

## Context
ユーザ型（struct/enum）に演算子をどう効かせるか。Go は struct の `==` を構造的に自動提供し、
Rust は `derive`/`impl` による明示を要する。ADR-0005 では「Copy はユーザ型に自動付与しない」
と決めたが、等価性は複製と違い**無害**（値を複製せず bool を返すだけ）であり、態度を変えうる。

## Decision
- **`==` / `!=`（等価）**: struct/enum は**既定で構造的フィールド比較**ができる。`Eq` トレイトを
  実装した型はそれで**上書き**する。
- **`<` / `<=` / `>` / `>=`（順序）**: 構造的自動は**しない**。`Ord` の明示実装のみ。
- **`+` / `-` / `*` / `/`（算術）**: 構造的自動は**しない**。`Add` 等の明示トレイトのみ。

## Considered Options
- **全演算子をトレイト明示**（Rust 流）: 一貫するが `==` すら derive が要り煩雑。却下。
- **等価のみ構造的既定**（採用）: Go の利便と安全のバランス。「どのフィールド優先か・昇順か」
  「フィールド毎の加算が常に意味を持つか」が自明でない順序・算術は明示に倒す。

## Consequences
- **「Copy は自動でない（危険）が `==` は自動（無害）」という非対称は意図的**。複製は資源の
  二重化を招きうるので明示（ADR-0005）、等価は無害なので既定。
- 順序・算術は意味依存なので、トレイト実装で初めて使えるようにする。
- struct の構造的 `==` は codegen でフィールドを再帰的に比較して AND 合成する（実装課題）。
