# ADR-0006: トレイトのディスパッチは静的のみ（`dyn`/トレイトオブジェクトを持たない）

## Status
Accepted（設計確定。単相化ジェネリクス・トレイトの codegen はこれから。固有メソッドの
静的 emit は実装済み。）

## Context
トレイト導入にあたりディスパッチ方式を決める。`spec/type.md` には境界の書き方が2つある:

```
fn foo<T: Greet + Serialize>(x: T): string   // 型パラメータ経由
fn foo(x: Greet + Serialize): string          // 型パラメータなしで境界を型注釈に直接
```

後者を **静的**（具象型ごとに単相化）と読むか **動的**（vtable で実行時ディスパッチ＝
トレイトオブジェクト）と読むかで、メモリモデルと codegen が根本から変わる。
トレイトオブジェクトは**型を消去**するため、消去した値の所有・`&dyn` の借用寿命を
**所有権 DAG（ADR-0003: ライフタイム非注釈・自動推論）でどう追跡するか**が未踏。現状の
codegen は vtable も単相化ジェネリクスも未実装。

## Decision
- **ディスパッチは静的のみ**。トレイトは**単相化ジェネリクス**（`<T: Bound>`）で実現する。
- **`dyn`／トレイトオブジェクトは当面持たない**。異種コレクション（`[Drawable]` に Circle と
  Square を混在）は書けない。
- `x: Greet + Serialize`（型パラメータなしの境界型）は **引数位置限定の匿名ジェネリック
  パラメータの糖衣**（Rust の `impl Trait` 引数相当）。呼び出しごとに単相化する。
- **トレイト名を型位置に書けるのは引数のみ**。以下は将来拡張（`dyn` または `-> impl Trait`
  導入時）として保留:
  - 戻り値 `-> impl Trait`（単一の隠し具象型）
  - フィールド・`let` 束縛・異種コレクション（型消去＝`dyn` が要る）

## Considered Options
1. **静的のみ**（採用）: 既存の `@Type.method` emit の自然な延長。所有を具象型のまま追跡できる。
2. **`dyn` も最初から**: 型消去 × 所有権 DAG × ライフタイム非注釈の相互作用が未踏で重い。
   静的→動的は後から足せるが逆は辛い。却下（後日検討）。

## Consequences
- vtable 不要・単相化のみ。所有権 DAG は具象型のまま追跡でき、ADR-0003 と整合。
- **異種コレクションが書けない**のが当面の最大の制約。必要になったら `dyn` を後付けする。
- 境界型 `x: Greet + Serialize` の構文は残すが、意味は「単相化される静的境界」。
