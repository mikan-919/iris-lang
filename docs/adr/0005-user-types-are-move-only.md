# ADR-0005: ユーザ定義型は暗黙の Copy を持たない（move-only 既定）

## Status
Accepted（設計確定。複製の明示 `clone` と Copy 判定の現状は ownership 層に実装済み、
ユーザ型 move-only の徹底は trait/clone 整備とあわせて反映する。）

## Context
トレイト導入にあたり `Copy` / `Clone` をどう扱うかを決める必要がある。

- **構造的にコピー可能 ≠ コピーしてよい**。例: `type Fd = struct { raw: i32 }`（OS の
  ファイル記述子）は中身が `i32` ひとつで構造的には複製可能だが、複製すると二重 close の
  バグになる。**意味的には move-only にしたい**。「全フィールドが Copy なら型も Copy」と
  構造から推論すると、こうした move-only 型を**黙って Copy にしてしまう**。
- iris は **所有権を呼び出し側・型の表面に露出しない**（ADR-0003: ライフタイムも所有権
  DAG から自動推論し、注釈構文を持たない）。`impl Copy for T` のようなマーク/派生は、
  ムーブ/コピーという所有権の決定を型の API 面へ出すことになり、この方針と擦れる。
- ゼロコピー（move-only）が必須な場面が現実にある。既定でそれが**安全側**に倒れてほしい。

## Decision
- **暗黙 Copy はプリミティブに限る**: 数値・`bool`・`char`・不変参照 `&T`、および要素が
  すべて Copy のタプル。これは既存の内部判定 `src/sema/ownership/flow.rs` の `is_copy`
  の範囲。
- **ユーザ定義型（struct / enum）は構造によらず常にムーブ**。暗黙 Copy にはならない。
- **複製は明示 `x.clone()`**。当面はコンパイラが構造的ディープコピーを自動提供する。
- **`Copy` をユーザが実装/派生する構文は設けない**。所有権関連の振る舞いを型表面に出さない。

## Considered Options
1. **構造推論のみ**（全フィールド Copy → 型も Copy）: move-only 型を作れず `Fd` の例が
   黙って壊れる。却下。
2. **推論＋オプトアウト**（既定 Copy だが「move-only」宣言で外せる）: 宣言を忘れると穴が
   残る（安全側に倒れない）。却下。
3. **オプトイン Copy（Rust 流）**（ユーザ型は move-only、Copy をマーク/派生）: 安全だが
   所有権の決定を型表面に出す＝ADR-0003 と擦れる。却下。
4. **ユーザ型は常に move-only**（採用）: プリミティブのみ Copy、複製は明示 `clone`。

## Consequences
- **ゼロコピーが全ユーザ型の既定**。`Fd` のような move-only 型は何も書かずに安全。
  オプトアウト忘れのような穴も無い。
- 所有権の表面（`impl Copy` 等）が一切要らず、ADR-0003 の「所有権を露出しない」と一貫。
- 小さい数値構造体（`type Point = struct { x: f64, y: f64 }`）も暗黙 Copy にならず、
  `&p` 渡しか `p.clone()` が要る。**隠れたコピーが起きない＝性能が読める**利点と表裏。
- 将来、リソース所有型のカスタム複製が必要になったら `Clone` を「ユーザ override 可能な
  トレイト」へ昇格して再検討する（その時に本 ADR へ追記/後続 ADR）。
