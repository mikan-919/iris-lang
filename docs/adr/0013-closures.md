# ADR-0013: クロージャ／ラムダ — 捕獲は所有権 DAG が推論し、型は組込み関数型として単相化する

## Status
Accepted。設計確定（**本実装は未着手**。本 ADR は後続の実装プラン
[plans/050-closures-impl.md](../../plans/050-closures-impl.md) の前提となる設計判断を固定する）。
既存の確定 ADR と矛盾しないことを各決定で確認済み（[ADR-0003](0003-no-lifetime-annotations.md)
注釈なし・[ADR-0005](0005-user-types-are-move-only.md) move-only・
[ADR-0006](0006-static-dispatch-no-trait-objects.md) 静的のみ・
[ADR-0007](0007-generic-traits-no-associated-types.md) 関連型なし）。

## Context
iris にはクロージャ／ラムダが**全く無い**（`grep -ri "closure\|lambda" src/` が空）。これが
要石の欠落になっている: `Iterator<T>` トレイトは `for x in iter` まで縦断実装済み（ADR-0007）
なのに、**`map`/`filter`/`fold` アダプタが std に一つも無い**（クロージャが書けないため
イテレータ機構が生の `for` でしか使えない）。

クロージャは「書けば終わり」ではなく**設計の分岐点**である。最大の論点は**捕獲セマンティクス**:
変数をムーブで捕獲するか借用で捕獲するかを、**ライフタイム注釈なし**（ADR-0003）で所有権 DAG
が推論しなければならない。さらに型表現は ADR-0006（静的のみ・トレイトオブジェクト無し）と
ADR-0007（関連型なし）の制約下に収める必要がある。本 ADR はこれらを先に潰す。

`docs/spec/function.md` には既にラムダ構文 `let f = (x: number): number -> x * 2` と関数型
`type Func = (number, (number): number): void` が記述されている（STATUS.md では「未実装」）。
本 ADR はこの既存構文を正式採用し、意味論（捕獲・所有・codegen）を確定する。

## Decision

### 1. 構文（既存 spec を正式採用）
- ラムダは `(params): Ret -> body`。`->` が「ラムダの目印」。
  - **式本体**: `(x: i32): i32 -> x * 2`（式が一つ）。
  - **ブロック本体**も許す: `(x: i32): i32 -> { let y = x * 2; ... return y }`。複文が要る
    場合の自然な拡張で、`fn` の `{}` と同形。
- **引数型・戻り型の省略と推論**: 期待型が文脈から定まる位置（アダプタ引数 `f: (T): U` に
  渡す等）では省略でき、期待型から推論する: `v.iter().map((x) -> x * 2)`。期待型が無い
  単独の `let f = (x) -> ...` は推論できず**型注釈を要求**（エラー）。**理由**: 注釈なし
  （ADR-0003）はライフタイムの話で、引数型の双方向推論まで約束しない。期待型がある所だけ
  省略を許せば、最頻ケース（アダプタ渡し）は注釈ゼロで書け、曖昧な所は明示を促せる。

### 2. 捕獲セマンティクス（最重要）— 所有権 DAG が**捕獲ごとに**推論する
- **`move` キーワードを設けない**。捕獲が借用かムーブかは、所有権 DAG が**捕獲変数ごとに**
  使用と寿命から推論する（ADR-0003 の「所有権を表面に出さない」と一貫）。
  - クロージャが捕獲元より**長く生きない**（即時にアダプタへ渡され消費される等）→ **借用捕獲**。
    `v.iter().map((x) -> x * k)` の `k` は借用で捕獲され、`map` 呼び出し後も `v`・`k` は使える。
  - クロージャが**エスケープする**（戻り値・フィールド・より長命な束縛へ格納）→ 捕獲を
    **ムーブ**する。借用のままだとダングリングになるため。
- **Copy 判定は既存規則（ADR-0005）に従う**: 捕獲がプリミティブ（数値・`bool`・`char`・
  `&T`・全要素 Copy のタプル）なら**値コピー捕獲**、非 Copy ユーザ型は上記の借用／ムーブ。
- **`mut` 捕獲**（捕獲変数の書き換え）は、捕獲を `&mut` 借用として表す（クロージャが
  エスケープするなら所有ごとムーブ）。`mut` は宣言側修飾子という iris 哲学（CONCEPT.md）に
  沿い、クロージャ本体での書き換え可否は借用の種別（`&` か `&mut`）として DAG が扱う。
- **理由**: これは所有権 DAG が**既に存在する理由そのもの**（flow.rs のムーブ/借用推論）を
  捕獲へ拡張するだけで、新しい注釈も `move` 構文も要らない。最頻ケース（throwaway な
  アダプタ用クロージャ）で借用、エスケープ時のみムーブ、という安全かつ最良の人間工学に
  なる。「常にムーブ」は捕獲した `Vec` を map 後に使えず `clone` を強いる（却下、下記）。

### 3. 型表現 — 組込み関数型 `(T): U`。`Fn`/`FnMut`/`FnOnce` トレイトは**作らない**
- クロージャの型は**組込み関数型** `(T): U`（既存 spec の関数型構文）。各ラムダリテラルは
  **無名の具象クロージャ型**（捕獲環境を内包）を持ち、`f: (T): U` 引数に渡される位置で
  ジェネリック引数 `<F>` と同様に**単相化**される。
- **`Fn`/`FnMut`/`FnOnce` の三トレイトは導入しない**。**理由**: 呼び出し演算子をトレイト
  メソッドにすると戻り型を**関連型**で表す必要があるが、ADR-0007 は関連型を持たない。
  `Fn<Args, Ret>` のように型引数化すると煩雑で、かつ ADR-0006（トレイトオブジェクト無し）
  下では `dyn Fn` も書けないため三トレイトの旨味（動的ディスパッチ）が出ない。組込み関数型
  なら関連型もトレイトも不要で、単相化（ADR-0006）にそのまま載る。
- **FnMut/FnOnce 相当の区別は所有権 DAG に畳み込む**: 「環境を書き換える（FnMut）」「環境を
  消費する（FnOnce、一度しか呼べない）」は型の種類ではなく、捕獲の借用種別（`&`/`&mut`）と
  ムーブ消費として flow.rs が表現する。型 `(T): U` は一つで足りる。

### 4. 所有権 DAG への載せ方
- 捕獲は **flow.rs のムーブ／借用イベント**として記録する: 借用捕獲は借用辺、ムーブ捕獲は
  ムーブイベント。捕獲した借用の**寿命 = クロージャの寿命**として provenance を伝播する
  （ADR-0003 の自動推論の延長）。
- **ダングリング検出**: 捕獲した参照がクロージャより先に死ぬ場合は、既存のダングリング返却
  検出（flow.rs）と同じ機構でエラーにする。エスケープするクロージャが借用を捕獲しようと
  したら、DAG はムーブへ格上げするか（格上げ可能なら）、不可能ならダングリングとして報告する。
- **エイリアス規則（borrows.rs）**: `&mut` 捕獲はスコープベースの排他（既存の保守的規則）に
  従う。クロージャ生存中は捕獲した `&mut` が排他を保持する。

### 5. codegen 表現 — 捕獲環境 struct ＋ 単相化（既存 `@f.Type` に載せる）
- 各クロージャリテラルを **(a) 捕獲環境を詰めた無名 struct と (b) その環境を先頭引数に取る
  関数**へ落とす。`self` を struct 値／`ptr` で先頭に渡す既存メソッド規約（`codegen.rs:2967`）
  と同形。
- アダプタ `fn map<T,U,F>(it, f: F)` は**具象クロージャ型ごとに単相化**され、既存の
  monomorphization worklist（`codegen.rs:683,751`・`mono_symbol`）がそのまま
  `@map.<env-type>` を emit する。**vtable も関数ポインタも不要**（各特殊化で呼び先は静的に
  確定）。関数ポインタ表現は、クロージャを非ジェネリックなフィールド／異種コレクションへ
  格納する場合にのみ要るが、それは ADR-0006 が既に除外している。

## Considered Options

**捕獲セマンティクス**
1. **DAG が捕獲ごとに推論（採用）**: 注釈ゼロ・最良の人間工学・ADR-0003/0005 と一貫。
   実装は最も重い（flow.rs にエスケープ解析が要る）ため、v1 は**非エスケープ
   クロージャに限定**して着手し、エスケープ捕獲は段階導入してよい（下記 Consequences）。
2. **常にムーブ捕獲**: 実装は最も軽いが、即時消費の `map` クロージャでも捕獲を奪うため
   `clone` を強いる。アダプタという動機そのものを壊す。却下。
3. **借用既定＋宣言側 `move` 修飾子**: 推論は軽いが、所有権の決定を構文表面に戻す（ADR-0003
   の「所有権を露出しない」と擦れる）。却下。

**型表現**
- **`Fn`/`FnMut`/`FnOnce` トレイト（Rust 流）** vs **組込み関数型（採用）**: 三トレイトは
  呼び出しの戻り型に関連型を要求し ADR-0007 に反する。`dyn` 無し（ADR-0006）では動的旨味も
  無い。組込み関数型は単相化に直接載り、追加機構ゼロ。却下（トレイト案）。

## Consequences
- **イテレータアダプタが書ける**: `map`/`filter`/`fold` を std に追加でき（後続プラン）、
  構築済みの `Iterator<T>` 機構が初めて高階で使える。最初の受け入れ目標は
  `docs/spec/function.md` のアダプタ例（実走テスト）。
- **v1 スコープの線引き**: 採用案 1 は実装が重いので、**v1 は非エスケープクロージャ
  （アダプタ即時消費）に限定**してよい。この範囲なら捕獲は常に借用／値コピーで済み、
  エスケープ解析を後回しにできる。エスケープするクロージャ（戻り値・格納）は v2 で
  ムーブ捕獲を足す。線引きは plan 050 が明記する。
- **設計スパイクの結論（codegen は物理的に成立する）**: 既存 codegen を確認した結果、
  クロージャは新規の関数ポインタ機構を要さず、**捕獲環境 struct ＋ 既存 monomorphization
  worklist**（`@f.Type` emit, `codegen.rs:683,751,1040`）にそのまま載る。struct は既に値渡し
  され（`codegen.rs:2967`）、現状 codegen に関数値表現は無い（`grep fn_ptr/FunctionType` が空）
  ため衝突も無い。`map` 一個の単相化 IR は「環境 struct を先頭引数に取る `@map.<env>` を
  emit する」形になり、現行機構の自然な延長。**物理的成立を確認**。
- **異種クロージャは書けない**: ADR-0006 の帰結として、型の違うクロージャを同じ
  `[(T):U]` コレクションに混ぜることはできない（型消去＝`dyn` が要る）。必要になったら
  ADR-0006 の `dyn` 後付けと合わせて再検討する。
- 後続の全クロージャ実装（plan 050）と `Iterator` アダプタの土台。レビューは「捕獲の
  デフォルトが ADR-0005 と整合するか」「トレイトオブジェクト無し（ADR-0006）を崩して
  いないか」を最重点で見ること。
