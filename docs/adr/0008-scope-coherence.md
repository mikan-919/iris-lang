# ADR-0008: コヒーレンスは `use` スコープ内で一意（グローバルなオーファン規則は採らない）

## Status
Accepted・一部実装（単一プログラム内では同一キー `(Trait<引数>, Type)` の重複実装を型検査で
拒否する（`check_conformance`）。`use` スコープ相対の可視性に基づく強制はモジュールシステム実装時。）

## Context
ADR-0004 のメソッド解決は「`m` の提供元集合」が**決定的**であることに依存する。
モジュール（`use std.lib`、`spec/module.md` にあるが未実装）が入ると、複数モジュールが
同じ `(トレイト, 型)` を実装しうる。提供元が二重になると解決が壊れる。

## Decision
- **グローバルなオーファン規則／コヒーレンスは採らない**。別々のモジュールが独立に同じ
  `impl Iterator<i32> for C` を持ってよい（retroactive な実装を許す）。
- **不変条件**: `use` で可視な範囲で、各 `(トレイト<型引数>, 型)` の実装は**高々1つ**。
  解決の提供元集合は **import に相対的**。
- **同一キーの実装が同時に可視になったら即エラー**。同一キー（同じ `(トレイト<引数>, 型)`）は
  `#` でも選べないため、可視になった時点で弾く。選択 import で回避する。
- 別トレイトの同名メソッド衝突は従来どおり `#`（ADR-0004）で解く。

## Considered Options
- **Rust 流オーファン規則**（グローバル一意・retroactive 不可）: 健全だが、ライブラリが
  既存型へ後付け実装できない硬さ。却下。
- **グローバル重複検出**（どこでも実装可・全体で重複ならエラー）: グローバル協調が要る。却下。
- **スコープ一意**（採用）: 可視範囲で一意。柔軟かつ ADR-0004 の決定性を保てる。

## Consequences
- モジュールが既存の型・トレイトへ**後付けで実装を足せる**柔軟さを得る。
- 代償: ある型のトレイト挙動が、どのモジュールを `use` したかで**プログラム間で変わりうる**
  （Rust が禁じる incoherence をスコープ限定で許容する）。
- 強制が「オーファン規則」か「可視重複検出」かの具体機構は、現状 std 前置の単一プログラムでは
  実害が無いため、モジュールシステム実装時に詰める。
