## Context
This document summarizes an ongoing design discussion for a new programming language targeting WebAssembly (WASM), with a focus on:

- Simple compiler implementation
- Strong memory safety guarantees
- Minimal runtime overhead
- Global optimization potential

## Current Design Direction

### Core Execution Target
- WebAssembly (WASM)
- Emphasis on low runtime cost and predictable execution

### Memory Model (Current Direction)
- Single ownership model forming a Directed Acyclic Graph (DAG)
- Ownership defines memory lifetime deterministically
- No garbage collector (GC) or reference counting (ARC) intended

### Reference System
- References are not raw pointers
- References are derived from ownership DAG structure
- References are guaranteed safe via compile-time reachability proofs
- No null references in valid programs

### Structural Model
- Program structure modeled as ownership DAG
- Cycles are not allowed in ownership graph
- Cycles may exist only in non-owning reference graph

### Compilation Strategy
- Local DAGs used for fast incremental compilation
- Global DAG used for full correctness verification and optimization
- Design aims to allow local reasoning with global guarantees

### Optimization Philosophy
- Shift toward global optimization language design
- Compiler is responsible for whole-program consistency analysis
- Local development experience should remain simple

## Key Open Questions

1. What exact restrictions define invalid programs?
2. How strictly should cycles be prohibited (ownership vs reference layer)?
3. What degree of reference flexibility is allowed without reintroducing GC/ARC?
4. How to balance local compilation independence vs global optimization dependency?

## Constraints Identified

- ARC is rejected due to implicit runtime behavior concerns
- GC is undesirable due to runtime overhead
- WASM environment favors deterministic memory layout
- Ownership-based model is preferred for runtime simplicity
